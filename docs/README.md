## The design record

Every phase was specced before it was built and planned before it was written.
Both sets are dated, append-only records rather than living documents, so a
file describes what was intended the day it was written, which isn't always how
the code looks now. The code is the current truth. These explain how it got
there, and why.

- **[specs/](specs/)** answers *what and why*: the physics being modelled, the
  fidelity tier it lands in, what is deliberately neglected, and how the result
  will be validated.
- **[plans/](plans/)** answers *how*: the task-by-task implementation sequence
  that turned each spec into working code and tests.

### Reading paths

Start with two documents. The original
[requirements and design](specs/2026-07-04-atom-sim-requirements-design.md)
sets out the provenance system everything else threads through, and
[Phase 1, Hydrogen Honestly](specs/2026-07-05-phase1-hydrogen-honestly-design.md)
builds the whole vertical slice, analytic solution to browser.

After that, the phases fall into five threads:

| Thread | Phases | Where it lands in the code |
|---|---|---|
| Hydrogen in closed form | 1 | `analytic/` |
| Structure beyond the gross levels | 9 Dirac, 10 Zeeman, 11 Stark, 12 hyperfine | `analytic/dirac.py`, `zeeman.py`, `stark.py`, `hyperfine.py` |
| Many electrons | 6 and 7 screened atoms, 21 and 26 Hartree-Fock, 27 and 29 total density | `numerics/`, `hf_atom.py`, `screened_atom.py` |
| Light | 13 to 16 transition strengths, 17 populations, 18 profiles, 19 optical depth, 20 absorption | `spectra.py`, `populations.py`, `broadening.py`, `transfer.py` |
| Counterfactual physics | 2 constants, 3 classical ghost, 4 and 5 force laws, 8 free-form V(r), 22 exchange off, 24 Pauli off | `constants_lab.py`, `classical.py`, `numerics/radial_solver.py` |

Presentation and delivery are covered by 25 (isosurfaces), 31 (guided tour),
and [web hosting](specs/2026-08-07-web-hosting-design.md).
