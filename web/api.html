The AtomSim API

Last updated 24 October 2026

Everything the app draws comes from a public HTTP API, and you can call it yourself. This page is the guide. The generated reference, with every field of every response, lives at /docs, and the raw schema at /openapi.json.

The one rule: every number says what it is

Every physical value in a response comes with a provenance object, and its fidelity field is one of exact (closed form), numerical (converged, with an error estimate where one exists), approximation (an honest simplified model, assumptions listed), counterfactual (physics deliberately changed, then solved properly) or visual_liberty (a presentational choice). The method, assumptions, error_estimate and refinement fields say how the value was made and what would make it better. If you pass a value on, pass its fidelity with it.

Internally everything is in Hartree atomic units: lengths in bohr, energies in hartree. Conversions to eV or picometres are made at the API boundary, and the provenance says so.

Quick answers: plain GET requests

  • /api/systems: every system you can ask about (hydrogen-like presets and atoms from He to Ca) and which models can speak for each.
  • /api/system/m500: one system by key. Keys of the form m<M> are an electron around a +1 nucleus of mass M electron masses, for any M from 1 (positronium) to 10000, and work as system= everywhere a hydrogen-like preset does.
  • /api/state/{n}/{l}/{m}?system=h: the energy, ⟨r⟩, |L|, closed-form expectation values and a live virial check for one state.
  • /api/levels?system=h and /api/spectrum?system=h: the level ladder and the emission lines, the latter beside vendored NIST data where it exists.
  • /api/radial/{n}/{l}?system=h: R(r) and P(r) on a grid.
  • /api/dirac-radial/{n}/{l}?z=80: the exact relativistic (Dirac) radial functions of a one-electron ion, every j, beside Schrödinger.
  • /api/nodes/{n}/{l}/{m}?basis=real: where ψ is exactly zero.
  • /api/cascade/{n}/{l}?system=h: how an excited level decays, with branching ratios, photons per atom on each line, and populations in time.
  • /api/rabi?n1=1&l1=0&n2=2&l2=1&intensity=1e6&detuning=0: one transition driven by a laser (W/m², MHz), Rabi oscillations with real decay.
  • /api/finite-size?system=mu-h: how far the nucleus' size moves each level, and the muonic hydrogen Lamb shift each proton radius predicts.
  • /api/isoelectronic/2: the exact first two terms of the 1/Z energy expansion for a sequence (N = 2, 3, 4, 10 or 11 electrons), with NIST's ionization energy for every ion from Z = N to N + 10.
  • /api/rydberg/na: quantum defects of the s, p, d and f series of lithium or sodium to n = 20 in the screened model, beside NIST's.
  • POST /api/jobs/xray with {"z": 26}: the K-alpha X-ray line of one element from neon to krypton, by two Hartree-Fock solves of core-hole ions, beside Moseley's law and NIST's measured lines.
  • /api/exchange-hole?z=10&a=1.0: the Hartree-Fock density of a closed-shell atom along the line through the nucleus, with and without the exchange hole around an electron pinned a bohr from it.
  • /api/helium-correlation: helium's ground state from a Hylleraas correlated series, its correlation energy against Hartree-Fock, and the ionization energy beside NIST's.
  • POST /api/jobs/volume with {"n": 3, "l": 2, "m": 0}: |ψ|² on a 48, 64 or 96 cubed grid in a box fitted to hold 99.9% of the electron, as raw float32 from /api/jobs/{id}/data.
  • /api/dimensions?system=h: hydrogen's levels and degeneracies with the same -Z/r pull in two, three and four dimensions (counterfactual outside three).
  • /api/alpha-table?alpha_multiplier=2: relativity's share of the 1s binding for every element at a scaled fine-structure constant, and where the table ends.
  • /api/forcelaw?preset=powerlaw&p=1.3: levels under a changed force law, each with a virial check of its eigenvector.
  • /api/snippet?view=plane&n=3&l=1&m=1: the Python that reproduces a view with this package.
  • /api/reference/ionization: NIST's measured ionization energies, He to Ca, with their citation and retrieval date. 
curl "https://atomsim.fly.dev/api/state/2/1/0?system=h"

Heavy work: jobs

Sampling a cloud, slicing a plane, meshing an isosurface, evolving a superposition and solving Hartree-Fock all take long enough to run as jobs. The protocol is the same for all of them:

  1. POST a JSON body to one of /api/jobs/sample, /api/jobs/plane, /api/jobs/iso, /api/jobs/superposition or /api/jobs/hf. You get back {"id": ..., "status": "pending"}.
  2. Watch /ws/jobs/{id} on a websocket for progress, or poll /api/jobs/{id} until status is done or error.
  3. Fetch /api/jobs/{id}/meta for the description of the result, provenance included.
  4. Fetch /api/jobs/{id}/data (add ?channel= where the meta lists more than one) for the arrays, as raw little-endian float32. The meta's layout field says how to read them: a cloud is x, y, z interleaved; a plane is row-major with row i at z = axis[i] ascending.

Every job is a pure function of its request (sampling is seeded), so identical requests are answered from a cache, and the server keeps the most popular states precomputed. Finished jobs are kept for a short while only: fetch the data as soon as the job is done. 

import json, time, urllib.request
import numpy as np

base = "https://atomsim.fly.dev"
req = urllib.request.Request(
    base + "/api/jobs/sample",
    data=json.dumps({"n": 3, "l": 2, "m": 0, "count": 10000}).encode(),
    headers={"Content-Type": "application/json"},
)
job = json.load(urllib.request.urlopen(req))
while True:
    status = json.load(urllib.request.urlopen(f"{base}/api/jobs/{job['id']}"))
    if status["status"] in ("done", "error"):
        break
    time.sleep(0.2)
if status["status"] == "error":
    raise RuntimeError(status["error"])
meta = json.load(urllib.request.urlopen(f"{base}/api/jobs/{job['id']}/meta"))
raw = urllib.request.urlopen(f"{base}/api/jobs/{job['id']}/data?channel=positions").read()
points = np.frombuffer(raw, dtype="<f4").reshape(-1, 3)
print(points.shape, meta["provenance"]["fidelity"])

Limits

Job creation is rate limited per client: a burst of 80, refilling at one job every three seconds. A refused request gets a 429 with a Retry-After header. The plain GET endpoints are not limited. It is one small shared machine, so please be kind to it, and if you need a lot of results, run the package locally: it is the same engine.

Running it yourself

The engine is a Python package, and every endpoint here is a thin wrapper around a function you can call directly. Each view in the app has a "Reproduce in Python" fold with the exact call. The source and setup instructions are on GitHub.
